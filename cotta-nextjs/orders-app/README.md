# TableFlow — אפליקציית הזמנות עצמאית

אפליקציה עצמאית עם שרת Node.js, מסד SQLite, תפריט לסועדים, ניהול ומסך מטבח. אין תלות ב־Next.js לצורך הפעלתה.

## הפעלה

Node.js 22.13 ומעלה נדרש (מומלץ Node 24 LTS). בחבילה העצמאית:

```sh
npm install
npm start
```

בתוך פרויקט COTTA ניתן להריץ `npm run orders` מהתיקייה הראשית. `npm run dev` או `npm start` מריצים את האתר והמערכת יחד.

- ניהול: `http://localhost:4100/admin`
- מטבח: `http://localhost:4100/kitchen`
- טייק אווי: `http://localhost:4100/takeaway`
- שם משתמש התחלתי: **פיצה**; סיסמה: **123**.

## שירות במסעדה

1. מתחברים לניהול ופותחים ״שולחנות וקודים״.
2. מזינים כתובת שהטלפונים יכולים להגיע אליה: דומיין HTTPS או כתובת IP ברשת המקומית. `localhost` לא נגיש מטלפון אחר.
3. מפיקים ומדפיסים קוד ייחודי לכל שולחן. המספר והחתימה נכללים בקוד; מספר שולחן בלבד אינו מאפשר שליחה.
4. כל סועד סורק, בוחר שם ומצטרף. מזהה UUID חדש נוצר לכל סועד בביקור. שם זהה אינו מאחד סועדים. המזהה נשמר ב־sessionStorage בלשונית ובמסד השרת.
5. הצוות רואה ריכוז לפי ביקור בשולחן, שם סועד, מזהה, מספר סועדים, מנות, כמויות, הערות ומחירים. אפשר לעדכן את מספר הסועדים בניהול השולחנות.
6. הסטטוסים: חדשה → בהכנה → מוכנה → הוגשה / נאספה. אפשר לבטל חדשה או בהכנה. אפשר להדפיס הזמנה או ריכוז שולחן דרך מערכת ההדפסה של הדפדפן.
7. משלימים או מבטלים הזמנות לפני סגירת ביקור. הסגירה מבטלת את מזהי הסועדים הקודמים; הסריקה הבאה פותחת ביקור חדש באותו שולחן. ביקור פג אחרי 8 שעות.

מסך המטבח מתאים גם לטלפון. העדכון מתבצע בכל 3 שניות. צליל התראה מופעל לאחר סימון התיבה, בהתאם להרשאות הדפדפן.

## טייק אווי

שם, מספר טלפון, מועד איסוף מבוקש ומנות. הלקוח מקבל מספר הזמנה וכפתור להתקשר למסעדה. אין סליקת אשראי ואין שמירת פרטי כרטיס. המנהל מסמן תשלום שהתקבל בפועל; לפני סימון זה אי אפשר להעביר טייק אווי להכנה. מועד האיסוף הסופי מאושר בשיחה עם המסעדה.

## תפריט ומדיה

התפריט נמצא ב־`menu.json` בחבילה העצמאית, או `../shared/menu.json` בפרויקט האתר. ניתן לערוך את המנות והמחירים בקובץ ולהפעיל מחדש. בממשק הניהול אפשר לעדכן זמינות ולהעלות MP4/WebM עד 20MB לכל מנה. הוידאו נשמר בשרת ומופיע בתפריט ובאתר COTTA.

התמונות נמצאות ב־`public/images/`. תמונות להמחשה מסומנות על המנות. ראו `SOURCES.md` בפרויקט האתר. מסך הגדרות העסק מאפשר לשנות שם, טלפון ומספר שולחנות; אפשר להריץ עותק נפרד לכל מסעדה.

## חיבור לכל אתר

קישור רגיל ל־`https://orders.example/takeaway`, או:

```html
<iframe src="https://orders.example/takeaway"
  title="הזמנת אוכל" style="width:100%;height:1000px;border:0"></iframe>
```

הניהול והמטבח נפתחים בכתובות `/admin` ו־`/kitchen` ומוגנים בכניסה. תפריט השולחן נפתח **באמצעות הקוד המונפק במערכת**. אין צורך לאפשר CORS כי כל אינטראקציות ההזמנה מתבצעות בתוך האפליקציה. באתר COTTA קיימת העברה דרך `/order/*` אל שירות ההזמנות.

## פריסה ושמירה

זהו שרת Node עם דיסק מתמיד, לא אתר סטטי. הפרויקט לא פורסם לאינטרנט. יש לפרוס על שרת/VPS או שירות Node עם volume קבוע; SQLite אינו מתאים לאחסון סטטי או למספר מופעים עם דיסקים נפרדים. אין תמיכה בפריסה ב־Sites/Cloudflare Workers, שבהם אין Node SQLite ודיסק מקומי מתמיד. לשימוש דרך Sites נדרש מעבר למסד נתונים נתמך ולסביבת השרת שלו.

אפשר להעתיק `.env.example` ל־`.env` ולהגדיר:

```dotenv
ORDERS_PORT=4100
ORDERS_USERNAME=פיצה
ORDERS_PASSWORD=replace-with-a-long-unique-password
ORDERS_PUBLIC_URL=https://orders.example
ORDERS_DATA_DIR=/data/tableflow
```

השרת טוען `.env` מתיקיית ההפעלה. ב־production יש להשתמש ב־HTTPS, להחליף את הסיסמה ההתחלתית ולהגן על הדיסק. מסד הנתונים, חתימות השולחנות והסרטונים נמצאים ב־`data/`; יש לגבות את התיקייה. לא נכללים בחבילת המקור נתוני לקוחות או סודות. הפעלה מחדש מנתקת את כניסת הצוות, אך משמרת הזמנות וביקורים. הדפסת הקודים נדרשת מחדש לאחר שינוי הדומיין, לא לאחר הפעלה מחדש.

לקוח שלא קיבל תשובה יכול לנסות שוב באותה לשונית: מזהה בקשה משמש למניעת שליחה כפולה, גם לאחר רענון. המחירים ומצב הזמינות נבדקים בשרת, ולא נלקחים מהלקוח.

## הזמנת מקום באתר

המערכת כוללת הזמנת מקום באמצעות API פנימי ואישור בממשק המנהל. ״הזמנות מקום״ מציג בקשות, טלפון, תאריך, שעה, מספר סועדים, אזור, הערות ומפת שולחנות יומית. ״הגדרות ישיבה״ מאפשר לשנות מושבים, אזורי ישיבה, זמינות שולחנות, שעות פעילות ומשך ישיבה (ברירת מחדל 90 דקות). כל שולחן מוגדר תחילה ל־4 מושבים ובפנים; יש להתאים למסעדה. שינוי מתנגש עם הזמנה מאושרת נדחה.

הלקוח מקבל קישור אישי למעקב באתר COTTA, עם סוד גישה בקטע hash שאינו נשלח כחלק מהכתובת לשרת. אין SMS, אימייל או ספק הזמנה חיצוני. בקשה ממתינה אינה חוסמת מקום; אישור משייך שולחן, ובדיקת החפיפה נעשית בתוך עסקת SQLite. ביטול של לקוח או מנהל משחרר את המקום. הזמנות שהושלמו ממשיכות לחסום את משך הישיבה המקורי עד סופו כדי שלא לפתוח מקום לאישור חופף בטעות.

API: `GET /api/reservations/availability?date=YYYY-MM-DD&party=2&area=any`, `POST /api/reservations`, `GET/PATCH /api/reservations/:id` עם Bearer token. ממשק COTTA משתמש ב־`/order/api/...`. ניהול מוגן: `GET /api/admin/reservations`, `PATCH /api/admin/reservations/:id`, `PATCH /api/admin/booking-config`. כל שעות המועדים לפי שעון ישראל. התמיכה היא בביקורים שמתחילים ומסתיימים ביום השירות עצמו, כולל סיום ב־24:00. לא כלולה התחלה אחרי חצות או איחוד שולחנות. בקשות והאישורים נשמרים במסד הנתונים גם אחרי הפעלה מחדש.
